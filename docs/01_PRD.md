## 1. Problem Statement (해결하려는 문제)

대형 매장(Food Depot 등)에 진열되어 있는 당사 제품의 재고 상태를 수기로 확인하고 발주를 수동으로 계산하는 과정에서 다음과 같은 문제가 발생하고 있습니다.
1. **결품 및 과다 재고**: 매장별 적정 재고(PAR Level) 기준 없이 직원의 감(Intuition)에 의존한 발주로 결품 혹은 과다 재고 발생.
2. **업무 비효율**: 현장 실사 후 사무실로 복귀하거나 유선으로 수량을 계산/전달하는 이중 작업 발생.
3. **입력 지연**: 매장 현장에서 즉시 발주가 들어가지 않아 출고 및 배송 리드타임이 늘어남.

**목표**: 현장 직원이 모바일 앱으로 진열대 재고를 입력하는 즉시, 사전에 등록된 매장별 PAR Level을 기반으로 부족분을 자동 계산하여 본사 WMS로 즉시 발주를 전송하는 원스톱 모바일 앱을 구축합니다.

## 2. Target Users (주 사용자)

| 사용자 유형 | 설명 | 핵심 니즈 |
|------------|------|----------|
| **현장 영업/MD (루트 세일즈)** | 매장을 정기 방문하여 진열 상태를 확인하고 재고를 채우는 담당자 | 복잡한 계산 없이 매장 진열대 앞에서 2~3분 내에 실사 및 발주 완료 |
| **매장 관리자 / 본사 물류팀** | 매장별 재고 실사 내역을 모니터링하고 출고를 진행하는 담당자 | 결품 없는 안정적인 매장 공급, 자동 접수된 정확한 발주 데이터 |

## 3. Core Features — MVP Scope (핵심 기능)

| # | 기능명 | 설명 | 우선순위 |
|---|--------|------|---------|
| **F-001** | 매장 선택 & 실사 세션 생성 | 방문한 Food Depot 매장을 선택하고 실사 세션을 개시 | P0 (필수) |
| **F-002** | 진열 순서별 실사 고속 입력 | 진열 동선 순서대로 제품을 노출하고 터치 증감/텐키로 재고 수량 초고속 입력 | P0 (필수) |
| **F-003** | 부족분 자동 계산 엔진 | 매장별 PAR Level - 실사 수량을 계산하고 박스(Case) 단위로 올림하여 발주량 산출 | P0 (필수) |
| **F-004** | 발주 검토 및 미세 조정 | 산출된 발주량을 확인하고 현장 특이사항에 따라 수동 증감 및 사유 메모 입력 | P0 (필수) |
| **F-005** | WMS 발주 즉시 전송 | 확정된 주문을 본사 WMS 주문 시스템(`orders`, `order_items`)으로 자동 등록 | P0 (필수) |
| **F-006** | 바코드(UPC) 스캔 | 카메라를 통해 제품 바코드를 스캔하여 해당 품목으로 즉시 포커스 | P1 (중요) |
| **F-007** | 오프라인 임시 저장 | 마트 내부 음영지역에서도 데이터 유실 없도록 로컬 임시 저장 및 자동 복구 | P1 (중요) |
| **F-008** | 매장별 동적 PAR Level 관리 | 매장별/품목별 적정 재고(PAR)와 진열 순서 비정기 수시 관리 (인라인 그리드 편집, 타 매장 설정 복사, CSV 일괄 업로드) | P0 (필수) |
| **F-009** | PAR 변경 이력 및 실사 스냅샷 | PAR 기준 변경 시 변경자/사유 로깅 및 과거 실사 당시의 PAR 스냅샷 불변 보존 | P0 (필수) |
| **F-010** | Phone & Tablet 적응형 반응형 UI | 스마트폰(한 손 썸존 조작, 단일 열) 및 태블릿(2단 분할 Split-View, 고밀도 그리드, 상시 스캐너) 최적화 | P0 (필수) |
| **F-011** | 매장별 진열 품목(PAR) 필터링 및 현장 동적 품목 추가 | 각 매장의 이전 진열 리스트(PAR)만 실사 화면에 표시하고, 실사 중 Master Catalog(전체 아이템)에서 신규 진열 품목을 추가/영구 저장 | P0 (필수) |
| **F-012** | 반품(Return: Damaged/Out of Date) 및 매장 Credit 자동 등록 | 파손/유통기한 경과 등의 반품 아이템 등록 시 `(단가 - 단가의 5%) × 수량` 공식으로 매장 Credit을 자동 계산 및 등록 | P0 (필수) |

## 4. Out of Scope — MVP 제외 사항 (오버엔지니어링 방지)

- **AI 수요 예측 모델**: 판매 추세에 따른 동적 PAR 자동 추천은 MVP 이후 단계로 연기.
- **매장 POS 시스템 직접 연동**: 매장 자체 결제/POS 시스템 연동 없이 현장 실사 기반으로 운영.
- **네이티브 앱 스토어 배포**: 모바일 웹(PWA)으로 구현하여 즉각 배포 및 OS 제약 최소화.

## 5. Success Metrics (성공 지표)

| 지표 | 목표값 | 측정 방법 |
|------|--------|----------|
| **매장당 실사~발주 시간** | **3분 이내** | 실사 세션 시작~발주 완료 시간 로그 측정 |

| **현장 입력 편의성** | 바코드 인식률 95% 이상 | 파일럿 사용자 만족도 조사 |

## 6. Constraints & Assumptions (제약 조건 & 가정)

- **기존 인프라**: 기존 WMS / Orderapp의 데이터베이스(Supabase) 및 주문 스키마와 직접 연동.
- **기기 환경**: 현장 직원의 스마트폰(iOS Safari, Android Chrome) 및 매장/카트용 태블릿(iPad, Galaxy Tab 등 768px~1024px+)을 모두 공식 지원.
- **네트워크**: 대형 매장 내부의 간헐적인 네트워크 불안정 상황을 필히 고려하여 설계.

## 7. Design Direction (디자인 방향)

- **Phone 모드 (< 768px)**:
  - 매장 진열대를 마주보고 선 상태에서 한 손으로 재고를 입력할 수 있도록 하단 집중형(Bottom Thumb Zone) UI 채택.
  - 대형 터치 타겟 (`+1`, `+5`, `+10`, `-1`, 텐키) 및 바텀 시트 스캐너.
- **Tablet 모드 (≥ 768px)**:
  - 2단 분할 레이아웃(Master-Detail Split View): 좌측 품목 리스트 + 우측 상세 품목 입력/텐키/계산기 및 실시간 카트 뷰.
  - 화면 전환 없이 카메라 뷰파인더와 품목 목록을 동시에 확인 가능한 고생산성 환경 제공.
- **시각적 명확성**: 현재 재고, 기준치(PAR), 부족 발주 수량이 명확히 구분되는 색상 및 뱃지 적용.
- **상세 UI 규칙**: [04_UI_GUIDE.md](04_UI_GUIDE.md) 준수.
